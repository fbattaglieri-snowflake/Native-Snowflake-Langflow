# ADR-007: Three-Plane Observability, Synchronized `Flow Activity` SQL Replication & Durable Governance Audit Outbox (`[G-A1]`, `[G-A2]`)

- **Status:** Accepted
- **Date:** 2026-10-17

> [!NOTE]
> **Under redesign (W3-R1).** Per-user attribution, query tags, and audit coverage are being completed. The decisions below describe the target design and are not fully live. Phase 0 changes are on a development branch and not deployed.

## Context
Users and administrators require full visibility into flow runs inside the Langflow `Flow Activity` UI while also querying structured traces and governance audit records directly via Snowflake SQL under active-role access controls, without risking secret leakage, duplicate side effects on retry, or resurrection of purged records.

## Decision
Separate observability into three distinct planes using canonical DDL table names (`[G-A1]`):

1. **Plane 1 — SPCS Container & OTLP Telemetry:** Structured JSON container logs (`stdout`/`stderr`) and OTLP spans/metrics routed to the Snowflake account Event Table.
2. **Plane 2 — Application Flow Traces (`Flow Activity` UI + Replicated Snowflake Tables):**
   - Preserve Langflow's native `Flow Activity` UI (`Runs` tab, session grouping, `Run`, `Trace ID`, `Timestamp`, `Input`, `Output`, `Token`, `Latency`, `Status`).
   - Attach `SnowflakeTraceReplicator` to `services/tracing/service.py` to replicate runs and spans asynchronously and idempotently (`MERGE INTO` on `run_id` / `span_id`) into **`<DATABASE>.<SCHEMA>.LANGFLOW_FLOW_RUNS`** and **`<DATABASE>.<SCHEMA>.LANGFLOW_FLOW_SPANS`** with Row Access Policies / role-filtered views.
3. **Plane 3 — Durable Governance Audit Outbox (`<DATABASE>.<SCHEMA>.LANGFLOW_AUDIT_LOG`):**
   - Record every object creation/modification, role switch, flow import/export, A2A publication/revocation, and `AUTHZ_ROLE_DENIED` denial via a transactional outbox keyed by idempotent `event_id` (fail-closed if audit intent cannot be persisted before privileged side effects).
4. **Integrity, Redaction & Deletion Semantics (`[G-A2]`):**
   - Outbox retries retransmit only the captured telemetry payload and **never** re-execute a flow, tool, SQL query, or LLM inference.
   - Deterministic pre-sink redaction strips `Bearer`/PAT/JWT/OAuth tokens, passwords, `access_roles`, cryptographic replay blobs (`encrypted_content`, `thinking.signature`), and masks raw PII spans emitted by `AI_REDACT` in `detect` mode before writing to local or Snowflake sinks.
   - Deleting a run in the UI sets a soft-delete tombstone (`deleted_in_ui_at`) without deleting `<DATABASE>.<SCHEMA>.LANGFLOW_AUDIT_LOG`, and an anti-resurrection tombstone filter prevents purged records from being re-inserted.

## Consequences
- 100% parity between `Flow Activity` UI and SQL tables, zero secret/PII leakage in traces, and tamper-evident governance auditing.

## v0.8.6 Update

Telemetry is unified: one RUN row per execution, spans synced in batches when the run closes, and role switches audited.

A span that cannot be linked to a single live run is attributed to a derived run id: `run_id` and `trace_id` are `NOT NULL` in the spans table, and one row without them would reject its whole batch on every sync.
