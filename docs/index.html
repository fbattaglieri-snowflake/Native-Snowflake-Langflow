How it works, in three steps

Langflow is a visual editor: you drag nodes onto a canvas and connect them. This project keeps the editor as it is and adds what it needs to work inside a Snowflake account.

Step 1

Pick a role

Choose a Snowflake role in the top bar. Every query in every flow runs under it. Only roles granted to you are listed.

SUPPORT_READER
MAINTENANCE_ANALYST
DATA_ENGINEER
Step 2

Set the flow Context

Tick the databases, schemas and objects this flow may use. Node dropdowns then show only those, and SQL on anything else is refused.

SERVICE_TICKETS
TICKETS_ANALYTICS
DOC_SEARCH

Step 3

Connect nodes and run

Drag Snowflake nodes next to the standard Langflow ones, wire them, and talk to the result in the Playground or call it as an API.

If the role cannot, the node says so

A node can use an object only when both the active role and the flow Context allow it. When they do not, the node fails with a clear error. Nothing falls back to a more powerful role.

Why it matters to the business

For people who decide what gets built, and want to see it working before anyone writes code.

An idea becomes something you can try

A use case is drawn on a canvas and tested in a chat in the same sitting. The conversation moves from slides to a working flow.

Data stays in the account

The editor runs as a container in Snowpark Container Services, next to the data. Nothing is copied to an outside tool to build a prototype.

Governance you can show

The role is visible in the top bar and each flow lists the objects it may touch. Security teams see the same rules they already manage.

Compare approaches before choosing

Send one question to a Cortex Agent, an agent with tools and a plain language model, side by side, and look at the answers together.

Every run leaves a record

Runs, steps and audit events are written to Snowflake tables. Anyone with access can review what a flow did using SQL.

Workflows that start from the data

A flow can begin on a schedule, when a table changes, when a file lands on a stage or when an alert fires. No one has to press run.

Your first ten minutes

You need a running instance. To deploy your own, follow the deployment guide.

Sign in and pick a roleminute 1

Open the service endpoint, sign in with your Snowflake login and choose a role in the Role selector. Start with the least powerful role that can read your data.

Create a flow and set its Contextminute 2

Start a new flow, press Context and tick the objects it needs: for a first try, one semantic view and one Cortex Search service.

Place five nodesminute 4

Drag in Chat Input, Agent and Chat Output. Add Cortex Analyst and Cortex Search, switch both to Tool Mode and connect them to the Agent.

Ask a question in the Playgroundminute 6

Ask something that needs a number, then something that needs a document. Watch which tool the agent picks for each.

Give it a memoryminute 8

On the Memories page create a memory, then add an Agent Memory node in Tool Mode. Open a new chat and check what it remembers.

Read the traceminute 10

Open Traces to see each step of the run, or query the telemetry tables with SQL.

Keep the Context narrowFewer objects means shorter dropdowns and an agent that is easier to reason about.
Reselect the role after a restartAfter the service restarts the role is empty on first load. Pick it again before using a flow.
Set Sender on Message HistoryA Language Model output has no sender. Set it on the node that stores the turn.
Load files outside the editorUpload files to a stage with Snowsight or the CLI. The nodes read them from there.

What it does not do yet

Better to read this before you plan a demo than to find out during one. The full list is in the README.

Not ready for production

It is under active testing. Run your own qualification and security review first.

Tested on AWS only

Other clouds have not been tried.

No file upload from the browser

Load files on a stage with Snowsight or the CLI.

External Volumes are untested

Creation is implemented but has never run against a real bucket.

Queries run as the service

They are limited to the role you select. Running as the signed-in user exists but is off by default.

One instance

The Langflow database sits on a block volume, so the service runs a single replica.

Cortex Analyst returns the full record

Outside Tool Mode the node gives back the API response as JSON, which uses more tokens in a prompt.

Decision ratings vary

In comparisons they are close to each other and change from one run to the next.

Try it, then say what broke

The most useful feedback right now is a flow that did not behave the way you expected, with the question you asked and the role you used.
